Earendil Ships Pi 1.0 — and an Agent That Never Has to Wake Up

earendil.com · October 1, 2026 · 938 pts on HN · 310 comments

Pi started as a side project by Austrian developer Mario Zechner, creator of the libGDX game framework, and has spent the past year quietly becoming one of the most-used terminal coding agents outside the big three vendors. Earendil — Armin Ronacher's AI studio — acquired it this spring; Zechner stayed on as a shareholder and kept steering the roadmap. Version 1.0, shipped October 1, adds Codemode for native Model Context Protocol support alongside non-LLM models, deferred tool loading so a session doesn't pay the context cost of tools it never calls, and cache warming tuned specifically for Anthropic's models. Earendil says "hundreds of thousands" of people now run Pi every week; the repo passed 45,000 GitHub stars and 2,000 third-party extensions back in May, before this release even shipped.

The same day, Earendil also shipped Pi Durable, pitched as an experimental substrate for agents that run for hours or days rather than a single terminal session — the kind of long-horizon task that keeps falling over when the process watching it dies. Pairing a hardened 1.0 with an explicitly experimental durability layer is a deliberate sequencing choice: ship the thing people already trust first, and let the riskier bet ride alongside it rather than inside it.

310 comments is a lot for a point release, and the MCP-native Codemode is drawing the most scrutiny — less because anyone doubts MCP has won and more because "native support" from a non-Anthropic agent reads as a signal of how settled the protocol has become. Cache warming built specifically for Anthropic models is the quieter tell: a third-party coding agent is now tuning its defaults around Claude's cost curve, not a generic LLM API.

"A third-party coding agent is now tuning its defaults around Claude's cost curve, not a generic API."

DeepSeek Built a Harness Where the Agent Loop Itself Is a Plugin

deepseek.com · Developer preview, resurfaced October 1, 2026 · 41 pts on HN · 14 comments

DeepSeek Harness has been in developer preview since August, released alongside V4 Pro, but it's back on the front page today behind a new official landing page. The pitch is architectural, not feature-based: everything — models, tools, skills, sessions, sandboxes, filesystems, the orchestration loop itself, even other coding agents — is a plugin running on a micro-kernel called Cordis. Standard mode gives you the full agent: filesystem tools, shell, web search, subagents, plan mode. Minimal mode strips it to two tools, bash and a string-replace editor, and lets you build back up from there.

The positioning is not subtle. Nearly every piece of coverage reaches for the same comparison: this is DeepSeek's answer to Claude Code, shipped MIT-licensed so anyone can fork the loop instead of trusting a vendor's defaults. "Everything is a plugin" is also a direct rebuttal to the fixed-workflow model that Claude Code and most of its imitators use — DeepSeek is betting developers who've hit the ceiling of a single hardcoded loop will pay in setup complexity for the ability to swap out the orchestration logic itself.

The modest 41 points and 14 comments on today's resurfacing undersell the stakes. An MIT-licensed, fully pluggable agent harness from the one lab with both the model and the infrastructure budget to make "don't trust a vendor's loop" a credible pitch is worth watching, even in a week where it's pulling a fraction of the attention Pi 1.0 drew one spread over.

"A direct rebuttal to the fixed-workflow model Claude Code popularized — and DeepSeek has the budget to make it credible."

An Open Router Matches GPT-6 Astra at Half the Cost — By Barely Using It

github.com/weave-os · Show HN · October 1, 2026 · 97 pts on HN · 32 comments

Weave Router 2.0 is a drop-in layer that sits in front of a coding agent — Claude Code and Codex are both named as supported hosts — and decides, per task, which model actually handles it. Benchmarked against GPT-6 Astra on Terminal-Bench 4.0 and SWE-Atlas, it matches Astra's pass rate on both while running at 52% and 54% of Astra's cost respectively, and 2.2–2.5x faster. The trick isn't a smarter model; it's knowing when not to use the expensive one. Astra gets the gnarly debugging and system-design work; DeepSeek V4 Flash picks up the routine frontend changes.

This is the second story in this issue built on exactly this premise — that a frontier model is a resource to be rationed by a cheaper classifier sitting in front of it, not the thing doing every unit of work. Cloudflare's Clef, two spreads over, is the infrastructure version of the same idea. Weave Router is the applied version, running inside the actual coding-agent loop developers already use.

The Show HN thread's sharpest pushback isn't about the benchmark numbers — it's whether "matches Astra's pass rate" survives contact with tasks outside Terminal-Bench and SWE-Atlas, both of which the maintainer used to tune the router in the first place. Worth watching whether the 2x speed claim holds once people run it against their own repos instead of the eval suite it was built against.

"A frontier model is a resource to be rationed by a cheaper classifier — not the thing doing every unit of work."

Cloudflare Doesn't Want to Build the Next LLM. It Wants to Build What Decides When to Call One.

blog.cloudflare.com · October 1, 2026 · 464 pts on HN · 170 comments

Clef and Clef-flash are Cloudflare's first open-weight models, and they're deliberately not generative. Post-trained from Qwen3.8-27B and Qwen3.5-9B and released Apache 2.0 on Hugging Face, they produce bounded, schema-constrained classifications instead of open-ended text — a frozen base model plus a two-stage attention-routing head that scores valid choices in parallel rather than generating tokens one at a time. p95 latency is 238.6ms for Clef and 122.4ms for Clef-flash, against 536ms for Cloudflare's own prior routing model, Jev.

The real product isn't the weights — it's the RL fine-tuning platform shipping alongside them. Capture production traffic through AI Gateway, generate rollouts on Workers AI, score the actions in Containers, update weights with a tool called Trainer, redeploy. It launches with a forward-deployed engineering team doing the work by hand, with an explicit roadmap to self-serve. That's a tell about where Cloudflare thinks the margin is in agentic infrastructure: not selling inference on a general model, but selling the loop that turns an enterprise's own traffic into a tiny model that makes one decision very fast.

170 comments split between people excited about a credible open alternative to routing-as-a-service and people noting that "decision model" is a rebrand of a classifier with better tooling wrapped around it. Both are true, and the tooling is the actual product.

"Not selling inference on a general model — selling the loop that turns an enterprise's own traffic into one fast decision."

What If the Model Edited Its Own Context Instead of Just Reading It?

arxiv.org · September 29, 2026 · 129 pts on HN · 28 comments

Context Language Models, from Rulin Shao and coauthors at the University of Washington and Meta Superintelligence Labs, treat the context window as a file the model can edit with ordinary bash commands rather than a transcript it can only append to. Delete a stale search result. Rewrite the plan. Compress twenty tool calls into two lines. Keep a running scoreboard at the top and update it in place. Every edit is synchronized back into what actually gets sent to the LLM server.

The numbers are worth sitting with if you've watched an agent session degrade as its context fills with dead weight. Zero-shot, CLMs beat Codex-style summarization by 11.4% relative on BrowseComp-Plus while using 21.5% fewer FLOPs, and beat it on a 12-hour EdgeBench run at 59% less compute. Steering the editing behavior with natural-language instructions through a standard skill-optimization loop adds up to 35.9 points on a held-out context-management task. An online RL variant improves Qwen3.5-9B's BrowseComp-Plus score by 47.6% on 12% fewer FLOPs.

This is the research answer to a problem every long-running agent framework in this issue is solving with engineering instead — Pi Durable, Weave Router's cost-aware routing, even Clef's fast classification all exist because context and compute are expensive to waste. CLMs attack it at the representation level: stop trying to summarize a transcript, and give the model direct write access to the thing it's going to read next.

"Stop summarizing the transcript. Give the model write access to the thing it's about to read next."

Turbopuffer Just Admitted the Vector Index Was Never the Point

turbopuffer.com · September 30, 2026 · 297 pts on HN · 79 comments

Dan Harrison's post announces turbopuffer v3, a rearchitecture of how the company lays out, writes, compacts, and queries data — and the headline admission is that the approximate-nearest-neighbor index, the entire reason turbopuffer exists as a company, is being demoted from primary index to "just another" secondary one. The team says they've pushed ANN-as-primary as far as it goes, and that a new primary layout is what actually lets them serve a wider range of query plans at bigger scale.

The quiet subtext is that most production RAG and agent-memory workloads were never pure similarity search to begin with — they're similarity search filtered by metadata, time ranges, tenant IDs, and permissions, and bolting that onto an ANN-first index was always the awkward part. Making ANN secondary is turbopuffer conceding that the filtering and metadata layer is the actual database, and vector similarity is one query plan among several it needs to support well.

79 comments and 297 points for an infrastructure migration post is a strong showing, and the thread's through-line is relief rather than surprise — a lot of people building retrieval systems had already converged on treating vector search as a feature of a real database rather than a database in itself. Turbopuffer just said it out loud and rebuilt around the admission.

"Vector similarity is one query plan among several — not the reason the database exists."

OpenAI Wants Chip-Design Agents. Synopsys Wants Revenue Share.

news.synopsys.com · September 30, 2026 · 175 pts on HN · 106 comments

OpenAI and Synopsys signed a multi-year agreement to jointly build GPT-Synopsys, a model specialized to operate Synopsys's EDA tools the way an expert engineer would: running the tools, interpreting outputs, iteratively optimizing a design, and closing timing and verification loops with a human reviewing the result rather than running each step. The deal includes revenue sharing and a joint go-to-market, with early customer engagements already underway.

This is the chip-design version of a pattern showing up everywhere else in this issue — a frontier lab partnering with the company that owns the domain-specific tools and workflow, rather than trying to replace that company's product with a general model acting alone. Synopsys keeps selling EDA software; OpenAI gets a wedge into a design process that runs for hours against tools no general-purpose agent can operate without years of domain-specific training data.

The security language in the announcement — customer design data won't train the model, encrypted in transit and at rest, configurable retention — is doing real work, not boilerplate. Chip designs are some of the most jealously guarded IP in any industry, and getting semiconductor customers comfortable running that IP through an OpenAI-trained model was always going to be the harder sell than the technology itself.

"A wedge into a design process that runs for hours against tools no general-purpose agent can operate alone."

A Historian Pointed Opus 5.5 at Dutch Colonial Archives and Found a New Dodo Sighting

resobscura.substack.com · October 1, 2026 · 104 pts on HN · 19 comments

Benjamin Breen's post walks through using Claude Opus 5.5 to surface what looks like a previously unnoticed 1615 Dutch account of hunting dodos, buried in the GLOBALISE archive of Dutch East India Company records. The method: download sources from the archive, run them through an embedding model for semantic search across languages, then have the frontier model read candidate passages and rank the strongest matches for a human historian to actually verify.

The part worth noticing for anyone who builds with these models rather than just chats with them is the parallelism. Breen describes spawning dozens of Opus copies to read through sources in multiple languages simultaneously, with the agent running its own embedding searches against new sources as they surface mid-research — not a single long chat, but a fan-out of narrow, disposable research tasks that converge on one ranked shortlist.

It's a small, quiet story next to this issue's infrastructure and business news, and that's exactly the point. Archival history is about as far from an agentic-coding benchmark as a use case gets, and it's converging on the same architecture — parallel subagents, embedding search, human-in-the-loop verification — that every coding harness in this issue is also building toward. The pattern is generalizing faster than the hype cycle around any one of its applications.

"The same architecture — parallel subagents, embedding search, human verification — is generalizing past coding."

No CUDA Required: One Go Binary Runs GGUF Models on Any GPU You Own

github.com/Vibra-Ingenn · Show HN · October 1, 2026 · 60 pts on HN · 9 comments

Janus is a single Go binary that serves .gguf models through llama.cpp's Vulkan backend, with an OpenAI-compatible API, hot-swap model loading, thinking-model support, and automatic chat-template detection. No Python, no Docker, no Ollama. The headline feature is the backend choice: Vulkan is a cross-platform compute API with drivers for AMD, Intel, and Nvidia, including integrated GPUs, where most local-inference tooling only accelerates on Nvidia through CUDA.

That matters more than it sounds for anyone running local models on hardware that isn't a 4090 — the laptop with an Intel iGPU, the desktop with an AMD card bought for gaming rather than inference, the machine that's been sitting idle because the local-LLM tooling ecosystem assumed CUDA as a precondition rather than an option.

The Show HN thread's main pushback is fair: there's no benchmark yet against vLLM or SGLang, and questions about Intel Vulkan driver overhead are unresolved. Nine comments and 60 points is a modest showing, but "runs anywhere Vulkan runs, in one binary" is the kind of utility that accumulates users quietly rather than trending — worth a star and a revisit in a few months.

"Runs anywhere Vulkan runs, in one binary — the kind of utility that accumulates users quietly."
