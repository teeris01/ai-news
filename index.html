Claude Code · Anthropic

The Regex That Grounded Thousands of Claude Code Users

twitter.com/theo · 865 points · 497 comments

Anthropic's load-shedding strategy for Claude Code turned out to involve a regex. Users discovered that if their git commit history contained the string "OpenClaw" — the name of a popular open-source Claude Code harness — Claude Code would either refuse to execute requests outright or silently apply extra throttling. A similar effect hit users with "Hermes" in their repos.

The discovery blew up on Theo's Twitter thread, which hit 865 points and nearly 500 HN comments within hours. The community reaction was a mix of fury and dark comedy. One commenter wrote: "I really want to stick with Anthropic given everything known about Altman, but man are they speedrunning the 'how to destroy your reputation' guidebook." Another: "Didn't they think about 'we need to make sure Claude Code itself is never banned'? Could have been as easy as including some Claude Code specific prompting traits."

The charitable read is that Anthropic was panicking under capacity pressure and made an engineering call that traded fairness for simplicity — a simple regex to identify power-users of competing orchestration layers and deprioritize them. The uncharitable read is that this is a taste of Claude-as-gatekeeper: a model that penalises you for using the wrong toolchain. Anthropic has not officially commented. One commenter summed it up: "Just admit that any pricing other than usage-based is completely unsustainable and is being phased out."

"It really seems they were panicking due to capacity and there was very little oversight with all this."

Opus 4.7 Knows Who You Are — Even When You Don't Tell It

theargumentmag.com · 115 points · 58 comments

Kelsey Piper, Vox's AI journalist, published a disquieting finding: Claude Opus 4.7 can identify her as the author of anonymous text samples with uncanny reliability. Not with web search. Not with memory enabled. Through the API in a fresh session. Just pure stylometry — reading her prose and matching it to a mental model of her writing built during training.

She tested it multiple ways: incognito mode, a friend's computer, direct API calls. She had a friend who lacks a substantial public writing footprint test text from a private Discord — Opus 4.7 failed on her, but correctly named two of her friends who do have internet presences, both of whom were in that same channel. The model isn't guessing randomly. It is doing something semantically close to authorship attribution at scale.

HN commenters began running their own experiments in real time. One wrote: "I just fed it my latest blog post draft (475 words), and it got it in one. Even knowing what to expect, I was very surprised." Another confirmed it works without thinking mode enabled — Opus just emits your name in two words. The implications for anyone who has ever written publicly under a pseudonym are severe. As one commenter put it: "One should assume that models will be good enough in the near future that privacy will be a thing of the past. Every anonymous post you made online can be traced back to you."

"The model isn't guessing randomly. It is doing something semantically close to authorship attribution at scale."

Security · AI Infrastructure

A Sand Worm Ate the AI Training Library

semgrep.dev · 299 points · 97 comments

PyPI credentials for Lightning AI — the company behind PyTorch Lightning, one of the most popular high-level training wrappers in the ML world — were compromised, and malicious code was silently pushed to versions 2.6.2 and 2.6.3 of the package. Semgrep's security team named the attack after Shai-Hulud, the sandworm from Dune, because of the distinctive "A Mini Shai-Hulud has Appeared" message embedded in the malware's output. The code steals credentials, authentication tokens, environment variables, and cloud secrets, then exfiltrates them by creating public GitHub repositories with Dune-themed names — within 24 hours, 2,200 such repos had appeared.

Andy from Lightning AI confirmed via HN comment that only PyPI packages were compromised, not the GitHub source. Users running NixOS via unstable channel got 2.6.2 automatically. A maintainer advised downgrading to 2.6.1 pending 2.6.4. The pip project had, coincidentally, released pip 26.1 just days earlier with a new --uploaded-prior-to flag specifically designed to pin against freshly-uploaded packages — exactly the scenario this attack exploited.

The HN thread evolved into a sharp debate about dependency hygiene at the intersection of AI tooling. One commenter predicted: "I think in the relatively near future we're going to start seeing sophisticated supply chain attacks into language model training data — vulnerabilities which look benign individually but when composed together in the agent plane introduce an exploit." The supply chain problem is getting harder as AI makes publishing code faster and auditing it slower.

"2,200 Dune-themed GitHub repos appeared in 24 hours, each one holding stolen credentials in near-plaintext."

AI Standards · Browser Wars

Mozilla Draws a Line in the Browser Sand Against Chrome's AI API

github.com/mozilla · 564 points · 207 comments

Mozilla filed a formal standards opposition to Google Chrome's proposed Prompt API — a browser-native interface that would let web pages directly invoke on-device large language models without routing through a server. The concern isn't the capability itself; it's the implementation. Mozilla argues the Prompt API as specified gives websites unconstrained access to a model that has been fine-tuned with the user's data, creating a novel fingerprinting and inference vector with no meaningful user consent layer.

The opposition landed hard: 564 points and over 200 comments on HN, where the core tension was well-articulated. On one side: on-device AI should be more private than cloud AI because nothing leaves the device. On the other: the Prompt API as designed means any website can query a model that may encode sensitive personal context, and the response becomes a side-channel. Mozilla's position is that the API needs a privacy-preserving design — perhaps ephemeral model instances per origin — before it ships.

This matters beyond the immediate spec debate. The browser is becoming an AI execution layer, and whoever controls that layer controls an enormous amount about how AI reaches end users. Chrome ships to roughly 65% of desktop browsers. Google shipping a Prompt API over Mozilla's objection would, effectively, be Google setting the default standard for on-device AI access unilaterally. The W3C standards process is about to get interesting.

"The browser is becoming an AI execution layer. Google shipping this unilaterally would be Google setting the default standard for on-device AI access."

Energy · Policy

Belgium Puts the Decommissioning Plans Back in the Drawer

dpa-international.com · 712 points · 656 comments

Belgium has officially reversed its long-standing policy of nuclear plant decommissioning, announcing it will keep its existing reactors operating and is now exploring extending their lifespans well beyond the original closure dates. The decision, confirmed by the Belgian government this week, marks a full policy reversal from the 2003 law that mandated a phase-out of nuclear power — a reversal that began tentatively after the 2022 energy crisis and has now been made permanent.

With 712 points and an extraordinary 656 comments, this was one of the most-discussed stories on HN this week. The debate split predictably: nuclear advocates pointing to Belgium's carbon-free baseload, critics asking about waste storage, but a clear plurality of the thread landed in "this was overdue" territory. The subtext on many threads: the AI industry's explosion in power demand has made every jurisdiction on earth rethink energy capacity planning. Data center operators are signing long-term PPAs for nuclear at unprecedented rates.

Belgium is not alone. Germany's political conversation about nuclear has shifted dramatically in two years. France never wavered. Sweden reversed its phase-out. Poland is building. The 2020s looked like nuclear's funeral; the 2026 consensus is closer to a careful rehabilitation. The question is whether the construction and regulatory pipelines can respond fast enough to matter for the decade's actual power gap.

"The 2020s looked like nuclear's funeral. The 2026 consensus is looking a lot more like a careful rehabilitation."

Privacy · Surveillance

LinkedIn Is Running a Silent Census of Your Browser Extensions

404privacy.com · 299 points · 121 comments

A researcher at 404privacy traced LinkedIn's client-side JavaScript and found a hardcoded list of 6,278 Chrome extensions. On every page load, LinkedIn probes each one by attempting to load a known static resource from that extension's bundle — if the resource loads, the extension is present. The results are packaged into an encrypted payload and injected as an HTTP header into every subsequent API request for the session. The scan runs silently, with no UI indicator, no consent prompt, and no opt-out mechanism.

The extension list is broad enough to be revealing. It includes religious community tools, medical reference apps, accessibility extensions, job search utilities, and — ironically — several privacy-focused ad blockers. The combination of installed extensions can infer tax bracket, job-seeking intent, and community affiliations with meaningful confidence, especially when stacked with other telemetry LinkedIn already collects.

A criminal investigation is reportedly now open in at least one European jurisdiction. The browser-level mechanism works because Chrome assigns stable, predictable IDs to extensions — Firefox randomises them per install, which breaks this technique. One HN commenter, watching their own network requests, noted: "Now the thousands of spammy 404 requests I was seeing on LinkedIn totally make sense." LinkedIn's stated justification — combating scraper extensions — covers perhaps a few dozen of the 6,278 on the list. The rest is dossier-building.

"The combination of installed extensions can infer tax bracket, job-seeking intent, and community affiliations — all without asking."

Internet Freedom · Spain

Spain's Parliament Moves to Rein In LaLiga's Internet Firewall

democrata.es · 380 points · 165 comments

Spain's parliament has announced it will take legislative action against LaLiga's practice of ordering mass IP address blocks to combat football stream piracy. The football federation had been granted court authority to demand ISPs block entire IP ranges during live match windows — a technically blunt instrument that has repeatedly taken down unrelated services, VPNs used by remote workers, corporate infrastructure, and individual websites that happened to share address space with piracy operators.

The collateral damage from LaLiga's blocks has been documented extensively by Spanish tech journalists and attracted sustained criticism from digital rights organisations. ISPs reported receiving block orders covering ranges that were, in practice, impossible to comply with without cutting off legitimate traffic at scale. One block order reportedly affected over 150,000 IP addresses in a single weekend.

The parliamentary intervention represents a rare case of a national legislature explicitly curtailing copyright enforcement overreach before it becomes further entrenched. The HN thread explored the broader pattern: rights-holder organisations that are granted blunt enforcement tools tend to use them with an indifference to collateral damage that is effectively unaccountable. The proposed legislation would require proportionality reviews before block orders can be issued and establish a fast-track appeals mechanism for services caught in the crossfire. It's a model other countries with similar arrangements are watching closely.

"One block order reportedly affected over 150,000 IP addresses in a single weekend — most of them entirely unrelated to piracy."

Security · Open Source

CopyFail: A Vulnerability That Wasn't Disclosed to the People Who Needed to Know

openwall.com · 312 points · 247 comments

A security researcher published a detailed account of a disclosure failure surrounding a vulnerability they're calling CopyFail. The core of the complaint: after discovering a significant flaw and initiating what they believed was a responsible disclosure process, the Gentoo Linux project was never properly notified — the disclosure went to upstream maintainers who handled it in a way that let a patched release ship without coordinating with downstream distributions that depended on the timing.

Gentoo users were therefore running vulnerable software during a window where a patch existed but had not been communicated to them. The researcher's openwall.com post is a meticulous account of exactly where the handoff broke down: who was contacted, when, what they replied, and what the downstream effect was. It's the kind of documentation that makes responsible disclosure work — or in this case, fail — legible to everyone.

The HN discussion, 247 comments deep, landed on a recurring tension in open-source security: coordination overhead is highest in the distributions and packaging layers that most users depend on, but those layers are also the furthest from where vulnerabilities are found and fixed. The incentive to just ship the patch and move on is strong; the incentive to work through a coordination matrix that includes Gentoo, Debian, Arch, NixOS, and a dozen others is weak. The result is a structural gap that attackers can reliably exploit.

"Gentoo users ran vulnerable software during a window where a patch existed — it just hadn't reached the right people."

Algorithms · Performance

You Can, in Fact, Beat the Binary Search

lemire.me · 226 points · 110 comments

Daniel Lemire — the performance researcher whose work on fast parsing, hashing, and integer compression has been a fixture on HN for years — published a new post showing that classical binary search can be beaten in practice, and not just in contrived benchmarks. The key insight is that binary search's branch-heavy structure interacts badly with modern CPU branch predictors: the comparisons at each step are hard to predict, and the resulting misprediction penalties accumulate across a log(n)-depth traversal in ways that dwarf the theoretical complexity advantage.

Lemire demonstrates alternatives: interpolation search (which exploits the distribution of key values), Eytzinger layout (which reorganises a sorted array into a cache-friendly heap-ordered layout that maps better to prefetch patterns), and branchless binary search variants that trade branch mispredictions for slightly higher instruction counts but execute in more predictable time on wide-issue pipelines. The performance gaps are real and not small — 30–60% improvements on typical sorted integer arrays on modern x86 hardware.

The HN thread expanded productively into where this matters: database indexes, in-memory lookup tables, embedded systems with limited branch prediction hardware, and anywhere a tight inner loop iterates over sorted data. The caveat that std::binary_search is rarely your bottleneck is warranted, but Lemire's point is more structural: when we teach algorithms, we teach complexity without teaching the hardware model, and the gap between the two increasingly shapes what fast code actually looks like.

"Binary search's branch-heavy structure interacts badly with CPU predictors in ways that dwarf the theoretical complexity advantage."

Pu.sh: A Full Coding-Agent Harness in 400 Lines of Shell

pu.dev · Show HN

A developer posted to Show HN: Pu.sh, a self-contained coding-agent harness implemented in approximately 400 lines of shell script. It wraps Claude (or any API-compatible LLM) with a tool-use loop, file read/write operations, bash execution, and a simple retry/checkpoint mechanism — the core primitives of an agentic coding workflow — without a framework, without a runtime, without dependencies beyond curl and jq.

The project is a pointed design statement. The explosion of agentic coding tooling in 2025–2026 has produced frameworks of considerable complexity — multi-process orchestrators, plugin registries, sandboxed execution environments, observability stacks. Pu.sh is a counter-argument: the actual logic of "give the model a task, let it read and write files, run code, loop until done" fits in a few hundred lines of shell that any developer can read, audit, fork, and run on a machine with no package manager involved.

The submission is particularly well-timed given the Claude Code / OpenClaw throttling story this week. Users frustrated with opaque behaviour in their primary agentic tools have concrete motivation to understand exactly what their agent harness does. Pu.sh is an existence proof that you can. The HN comments included several developers who had already forked and extended it for their own workflows within hours of the post going live — a signal that legibility and hackability remain powerful draws even as the polished tooling ecosystem matures.

"Pu.sh is an existence proof: the core of an agentic coding workflow fits in 400 lines of shell any developer can read, audit, and own."
